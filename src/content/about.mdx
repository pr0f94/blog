Application security engineer with a decade across software engineering and security, most of that time focused on AppSec. I bounce between both sides of the line: red teaming, exploit development, and vulnerability research one day, threat modelling, secure code review, and CI/CD security tooling the next.

What I actually spend my time on:

- Automating the boring bits of offensive and defensive work, so the interesting bits get more time
- Pushing security testing earlier in the SDLC without making developers hate it
- Securing AI and LLM systems, from the features users see down to the infrastructure they run on
- Independent vulnerability research and responsible disclosure
- Detection engineering around the build and deploy pipeline

The offensive and defensive sides of my work feed into each other. Exploit development changes what I look for in a code review. Threat modelling gives me new questions to investigate. Building security tooling is a way to take something learned from one application and make it useful for the next.

Outside my day-to-day work, I make time for independent research and hands-on learning. I like digging into unfamiliar systems, working out why something behaves the way it does, and sharing the parts that might save someone else a few hours down the same rabbit hole.

This site is where I publish CVEs, tools, and writeups as they come out. For the more formal version with employers and dates, the LinkedIn link is up top.
